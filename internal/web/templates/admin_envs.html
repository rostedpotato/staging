How it works

Stop and Start run docker compose stop / docker compose start for the whole env (watersheep, fisherman, database, redis, kafka, minio, ...), the same as running them in the env folder. Containers are only stopped, never removed, so data and Jenkins deploys keep working. Stopping takes a while because watersheep and fisherman are force-killed after about 10 seconds each; after Start, watersheep can take a minute or more to answer. The web backoffice is served by nginx and stays up. An env that is booked right now, or has a running deployment, is never stopped. Nothing starts an env automatically yet: start it before its booking begins.
