How it works

Stop and Start run docker compose stop / docker compose start for the whole env (watersheep, fisherman, database, redis, kafka, minio, ...), the same as running them in the env folder. Containers are only stopped, never removed, so data and Jenkins deploys keep working. Stopping takes a while because watersheep and fisherman are force-killed after about 10 seconds each; after Start, watersheep needs a moment before it answers (the card shows "starting" until it does). The web backoffice is served by nginx and stays up. An env that is booked right now, or has a running deployment, is never stopped.

Automatic stop/start — {{if .AutoPower}}ON{{else}}OFF{{end}}

When on: an env with no booking gets a stop countdown of 15 minutes after its last booking ended (or after this was switched on / the env was started, whichever is later). It is only stopped if no booking begins within 30 minutes after that moment; a new booking inside that window cancels the countdown. A stopped env is started 15 minutes before its next booking begins (right away if a booking is already running). A running deployment delays the stop. The countdown is shown here and on the dashboard. Manual Stop/Start still works; the schedule simply carries on from the new state. {{if .AutoPower}}On since {{fmtTime .AutoSince}}.{{end}}
