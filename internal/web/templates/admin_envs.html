How it works

Stop and Start run docker compose stop / docker compose start for the whole env (watersheep, fisherman, database, redis, kafka, minio, ...), the same as running them in the env folder. Containers are only stopped, never removed, so data and Jenkins deploys keep working. Stopping takes a while because watersheep and fisherman are force-killed after about 10 seconds each; after Start, watersheep can take a minute or more to answer. The web backoffice is served by nginx and stays up. An env that is booked right now, or has a running deployment, is never stopped.

Automatic stop/start — {{if .AutoPower}}ON{{else}}OFF{{end}}

When on: an env with no booking is stopped 15 minutes after its last booking ended (or 15 minutes after this was switched on / the env was started, whichever is later), and a stopped env is started 15 minutes before its next booking begins (right away if a booking is already running). A running deployment delays the stop. The countdown is shown here and on the dashboard. Manual Stop/Start still works; the schedule simply carries on from the new state. {{if .AutoPower}}On since {{fmtTime .AutoSince}}.{{end}}
